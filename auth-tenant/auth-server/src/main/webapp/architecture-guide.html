Core Architectural Layers
1

Edge Ingress Layer (Traefik)

Single entry point for all external traffic. Detects domain name from HTTP Host, looks up tenant mappings, and injects authoritative X-TENANT-ID and X-Tenant-Id headers before forwarding to internal services.

Traefik v3 CustomRequestHeaders Zero Trust Perimeter
2

BFF Layer (Spring Cloud Gateway)

Backend-For-Frontend acting as a confidential OAuth2 client. Holds access/refresh tokens securely in Redis-backed server sessions. The browser only sees an HTTP-only session cookie. Propagates tenant context downstream.

Token Relay Session Cookie No Token Exposure
3

Auth Server (Spring Auth 1.4)

Central OAuth2 / OIDC provider. Resolves tenant via TenantResolutionFilter, serves tenant-branded login UI and tenant-scoped theme CSS & vector logos from /tenant-assets/.

Spring Authorization Server Dynamic Branding Tenant Isolation
4

Frontend UI Layer (Panel)

Single SPA deployment serving all tenants. Dynamically adapts its theme (CSS variables) and vector brand assets based on tenant context without requiring separate rebuilds or deployments.

How Domain & Tenant Resolution Works

In an enterprise multi-tenant architecture, clients must never be trusted to dictate tenant identity arbitrarily. Identity is resolved in layers:

Resolution Step Layer Mechanism Fallback / Security Behavior
1. Host Header Resolution Edge / Traefik Evaluates Host header (e.g. Host(`smslocal.ir`)) and executes tenant middleware. If domain is unmapped, routes to default tenant or returns HTTP 404.
2. Header Injection Edge Middleware Appends authoritative X-TENANT-ID and X-Tenant-Id headers before routing to BFF/Auth. Strips any untrusted caller-provided tenant headers to prevent header injection.
3. Internal Binding Auth / Services TenantResolutionFilter reads header, binds resolved tenant code/ID to thread-local TenantContext. Cleared in a finally block to prevent thread pool leakage.
4. Dynamic Asset Dispatch Auth / Static Server TenantAssetController dispatches theme.css and logo.svg based on the resolved tenant code. Includes Vary: X-TENANT-ID and Cache-Control: no-cache to prevent cross-tenant CDN cache pollution.
Configuration & Code Highlights

1. Traefik Middleware & Header Injection (traefik_dynamic.yml)

http:
  middlewares:
    tenant-smslocal:
      headers:
        customRequestHeaders:
          X-Tenant-Id: "smslocal"
          X-TENANT-ID: "smslocal"

  routers:
    auth-smslocal:
      rule: "Host(`smslocal.ir`) && PathPrefix(`/auth`)"
      middlewares: ["tenant-smslocal"]
      service: "auth-service"

2. Dynamic Tenant Asset Controller (Auth Server)

@GetMapping("/tenant-assets/theme.css")
public ResponseEntity<Resource> theme(HttpServletRequest request) {
    String code = resolveCode(request); // Resolves from X-TENANT-ID header
    Resource res = new ClassPathResource("static/resources/tenants/" + code + "/theme.css");
    return ResponseEntity.ok()
            .contentType(MediaType.valueOf("text/css;charset=UTF-8"))
            .header(HttpHeaders.VARY, "X-TENANT-ID")
            .cacheControl(CacheControl.noCache())
            .body(res);
}

3. Client-Side Early Theme & Logo Injection (Panel index.html)

<!-- Prevents Flash of Unstyled Content (FOUC) by executing synchronously before DOM load -->
<script>
  (function() {
    var host = window.location.hostname.toLowerCase();
    var tenant = host.includes("smslocal") ? "smslocal" : 
                 (host.includes("asanlocal") ? "asanlocal" : "default");

    var link = document.createElement("link");
    link.id = "tenant-theme-css";
    link.rel = "stylesheet";
    link.href = "/tenants/" + tenant + "/theme.css";
    document.head.appendChild(link);

    window.logoUrl = "/tenants/" + tenant + "/logo.svg";
  })();
</script>
Architectural Recommendations & Best Practices

1. Never Expose JWTs to Browser

The BFF pattern guarantees that refresh tokens and access tokens stay on the server. The client gets an encrypted, HTTP-only, SameSite session cookie stored in Redis.

2. HTTP Vary Header on Assets

When the same URL (e.g. /tenant-assets/logo) produces different outputs based on X-TENANT-ID, always output Vary: X-TENANT-ID to prevent proxy/CDN cache collisions.

3. CSS Variables for Zero-Rebuild Theming

Define theme rules via CSS custom properties (--brand-primary, --accent) so changes to colors, fonts, or borders only require editing static CSS rather than recompiling JavaScript bundles.

4. Fallback Safety

Always maintain a default fallback theme and logo so unmapped domains or DNS variations gracefully display default branding instead of crashing or showing broken layout.
